# pairwise-gacha-pity

抽卡保底在跨卡池时提前触发：保底计数只存在本地缓存，换设备后清零；不同卡池共享同一个保底计数器，普通池抽数把限定池保底吃掉；十连里保底和普通抽取分开计算，第十抽的保底被跳过；概率公示按单抽写，十连保底没有在公示里体现；保底触发后计数器没有重置，下一抽又保底；跨卡池继承规则只按卡池 ID 判断，活动复刻换了 ID 后不继承；抽卡结果在服务器返回前就展示，断线后本地和服务器不一致；保底计数在批量抽卡循环里最后统一写回，中途失败丢计数；保底目标可选时没有记录选择，换目标后计数错位；概率表热更新后没有重算已累计的保底。gameplay/gacha_pity.py 是核心，tests/test_gacha_pity.py 15个红。要修的是：服务端持久化；按卡池组隔离；十连统一结算；公示同步；触发重置；继承按组；结果先确认；逐次写回；记录目标；热更新迁移。

## 运行

```bash
python -m pytest tests -q
```

初始状态：15 个用例失败。修复实现使全部用例通过，不要修改 `tests/` 下的测试。
